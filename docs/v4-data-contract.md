# สัญญาข้อมูล V4 สำหรับตรวจสอบการสำเร็จการศึกษา (ฉบับร่างสำหรับ Demo)

**สถานะ:** ข้อกำหนดสมมติสำหรับข้อมูลสังเคราะห์เพื่อสาธิตเท่านั้น (`v4-draft-1`) ไม่ใช่ข้อกำหนดอย่างเป็นทางการของมหาวิทยาลัยธรรมศาสตร์หรือสำนักทะเบียน ห้ามใช้ยืนยันว่าระบบเชื่อมต่อข้อมูลจริง ต้องตรวจและปรับให้ตรงกับสัญญาข้อมูลที่ได้รับอนุมัติก่อนนำเข้าข้อมูลจริง

## ขอบเขตและลำดับข้อมูล

V4 ปัจจุบันรับไฟล์ CSV แบบ **Demo เท่านั้น** ไม่มี client สำหรับเชื่อมต่อทะเบียนจริงและไม่มีสัญญาแลกเปลี่ยนข้อมูลที่ได้รับอนุมัติ ตัวอ่าน CSV ตรวจสอบแถว จากนั้น CLI บันทึก batch และผลการเรียนที่ผ่านการตรวจลง MySQL ส่วน API แบบอ่านอย่างเดียวคำนวณผลจาก `graduation_rule` ที่กำหนดไว้อย่างชัดเจน โดยทุกจุดต้องคงป้ายแหล่งข้อมูล `demo`

```text
CSV สังเคราะห์ -> CSV adapter -> ตรวจสอบและวางแผนนำเข้า -> CLI โหมด Demo -> snapshot ใน MySQL -> API แบบอ่านอย่างเดียว -> ผลตรวจสอบตามสิทธิ์
```

ใน repository นี้ยังไม่มี API ทะเบียนจริง credential สำหรับนำเข้าจริง หรือข้อตกลงแบ่งปันข้อมูล

## รูปแบบ CSV

ไฟล์ CSV แบบ UTF-8 มี header หนึ่งแถว คั่นด้วย comma และรองรับการ quote ตาม RFC 4180 ไฟล์หนึ่งไฟล์แทนข้อมูลส่งออกหนึ่ง batch ทุกแถวต้องมี `sourceBatchId` และ `exportedAt` ค่าเดียวกัน

| Field | จำเป็น | รูปแบบและความหมาย |
| --- | --- | --- |
| `studentId` | ใช่ | รหัสนักศึกษาสังเคราะห์ ตัวอักษร/ตัวเลข ASCII 1–20 ตัว ห้ามใส่รหัสนักศึกษาจริงใน fixture |
| `curriculumId` | ใช่ | รหัสหลักสูตร ตัวอักษร/ตัวเลข/ขีดกลาง 1–50 ตัว ต้องมีอยู่ในฐานข้อมูลเป้าหมาย |
| `academicYear` | ใช่ | ปี ค.ศ. 4 หลัก ตั้งแต่ 2000–2100 |
| `semester` | ใช่ | `1`, `2` หรือ `3` (ภาคฤดูร้อน) |
| `courseCode` | ใช่ | รหัสวิชา ตัวอักษร/ตัวเลข/จุด/ขีดกลาง 1–30 ตัว ระบบจะตัดช่องว่างออก |
| `credits` | ใช่ | ตัวเลข 0–12 เพิ่มครั้งละ 0.5 เช่น `3`, `1.5` |
| `grade` | ใช่ | หนึ่งใน `A`, `B+`, `B`, `C+`, `C`, `D+`, `D`, `F`, `S`, `P`, `U`, `W`, `I` |
| `sourceBatchId` | ใช่ | รหัส batch ตัวอักษร/ตัวเลข/จุด/ขีดล่าง/ขีดกลาง 1–100 ตัว และต้องเหมือนกันทั้งไฟล์ |
| `exportedAt` | ใช่ | เวลา ISO 8601 พร้อม timezone และต้องเหมือนกันทั้งไฟล์ |

ตัวอย่างต่อไปนี้ใช้รหัสสังเคราะห์และค่าเพื่อประกอบคำอธิบายเท่านั้น:

```csv
studentId,curriculumId,academicYear,semester,courseCode,credits,grade,sourceBatchId,exportedAt
DEMO0001,DEMO-GRAD-V4,2025,1,DEMO100,3,A,BATCH-DEMO-001,2025-12-15T09:00:00+07:00
DEMO0001,DEMO-GRAD-V4,2025,1,DEMO101,3,C,BATCH-DEMO-001,2025-12-15T09:00:00+07:00
```

## การตรวจสอบและนำเข้า

- header หาย/ซ้ำ, metadata ระบุหลาย batch, หรือ CSV ผิดรูปแบบ จะปฏิเสธทั้งไฟล์
- แถวที่ผิดจะถูกปฏิเสธเป็นรายแถว โดยเก็บเลขบรรทัดและ error code ไม่คัดลอกค่าทั้งแถวลง log
- รหัสหลักสูตรที่ไม่มีอยู่และรายการผลการเรียนซ้ำที่ขัดแย้งกันจะถูกปฏิเสธ
- ใช้ student, curriculum, ปีการศึกษา, ภาคเรียน และรหัสวิชาเป็นคีย์ของผลการเรียน การนำเข้าเดิมซ้ำต้องไม่สร้างแถวซ้ำ แถวเดิมนับเป็น unchanged ส่วนเกรดที่เปลี่ยนจะอัปเดตแถวเดิม
- ทุกครั้งที่นำเข้าต้องบันทึก batch, SHA-256 ของไฟล์, จำนวนแถวรวม, โหมดข้อมูล, ผู้นำเข้า, เวลาส่งออก และสถานะ ตาราง error เก็บเฉพาะ error code และเลขบรรทัด ไม่เก็บ transcript
- หากนำเข้าล้มเหลว/ไม่ครบ, มีแถวของนักศึกษาที่ถูกปฏิเสธ, ไม่มีข้อมูลต้นทาง หรือ snapshot เก่ากว่าเกณฑ์ ให้ผลเป็น “ยังสรุปไม่ได้” ห้ามแสดงเป็นผ่าน/ไม่ผ่าน

## กฎการจบและข้อจำกัดที่ทราบ

`curriculum_graduation_condition` เก็บข้อความแสดงผล ไม่ได้เก็บรูปแบบกฎที่เครื่องคำนวณได้ ระบบ V4 คำนวณเฉพาะเงื่อนไขที่มี `graduation_rule` อย่างชัดเจน หากไม่มีหรือไม่รองรับ ให้แสดง “ข้อมูลเงื่อนไขไม่ครบ” ห้ามอนุมานกฎจากข้อความภาษาไทย กฎใน `backend/fixtures/v4-demo/seed-demo.sql` เป็นกฎสมมติสำหรับ Demo เท่านั้น ไม่ใช่กฎจริงของหลักสูตรใด

การแปลงเกรดเป็นคะแนนใน `backend/src/graduation/evaluate.mjs` เป็นสมมติฐานสำหรับ Demo ต้องยืนยันความหมายของเกรด การแทนผลเมื่อเรียนซ้ำ เกรดถอน/ไม่สมบูรณ์ หน่วยกิตเทียบโอน และหลักเกณฑ์ GPA กับสำนักทะเบียนก่อนเชื่อมต่อจริง เกรดแบบผ่าน/ไม่ผ่านจะไม่ถูกนำไปเทียบกับเกณฑ์เกรดขั้นต่ำเป็นตัวอักษร หากแปลงเทียบไม่ได้ให้แสดงข้อมูลไม่ครบ

## ความเป็นส่วนตัวและสิทธิ์

- fixture ใช้รหัสนักศึกษาสังเคราะห์ `DEMO*` เท่านั้น
- นักศึกษาดูได้เฉพาะผลของตนเอง อาจารย์/เจ้าหน้าที่ดูได้เฉพาะนักศึกษาที่ได้รับมอบหมาย ผู้ดูแลหลักสูตรและผู้ใช้ที่ไม่เข้าสู่ระบบไม่มีสิทธิ์อ่านผลการเรียน
- ห้ามใส่ชื่อ อีเมล เกรดดิบ หรือแถว transcript ใน error log จำกัดการเข้าถึงไฟล์ต้นทาง และลบไฟล์ส่งออกชั่วคราวตามนโยบายเก็บรักษาข้อมูลที่ได้รับอนุมัติ
- สัญญานี้ยังไม่รองรับ live data ก่อนทำจริงต้องมีเจ้าของข้อมูล ฐานกฎหมาย/การอนุญาต นโยบายเข้ารหัสและเก็บรักษา การจับคู่ field และการยืนยันตัวตนของแหล่งข้อมูล
